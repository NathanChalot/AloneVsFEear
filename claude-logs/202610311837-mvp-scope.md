## Decisions

- **Book mode is the fallback for unwritten content** — the engine shows the text of the entry reached and the player applies it with manual actions; the whole game is playable at once and every content task replaces part of book mode. Rejected: rerolling unwritten results (skews the odds, hides most of the book), letting the player pick each time.
- **First version: one mission's path** — the engine follows the whole design, but only the content Bring Home the Bacon needs is written (exploration and Search tables, Street, Store, Farm, every creature's stats, creation tables, Skills, harm tables). Rejected: a bare skeleton with every table in book mode, all tables without events (much longer).
- **Bring Home the Bacon first** — it uses only core mechanics (Food, inventory, place visits).
- **Arcane Skills and campaign play come back into the MVP as step 2** — the user asked why Arcane Skills were out: it was only a scoping call from the first session. Step 2 is Close a Hell Gate, the Arcane Skill mechanism with Gate written (the other 10 learnable, effects in book mode), books, and campaign play. The MVP is done when the campaign is playable.
- **Spending XP is in the MVP**; save and resume, hunting with Clues and switchable rule options come after it.
- **Rules text in YAML** — raised by the user, to show the text on screen. IDs, dice, entries and text in YAML; behaviour in Python by ID; plain data (stats, weights) decided at the first written content (E6). The Markdown stays as the readable copy, fixed together with the YAML (the user chose to keep both). Everything is copied before step 1 is playable, replacing the Markdown-only cleanup. Rejected: parsing a strict Markdown layout, copying only what step 1 writes.
- **Manual actions go through the rules** (Injury offer, max caps, Food limit, reactions), never raw edits; they stay open during a fight when a special rule's text is shown, with creature Life up or down; they include going to a table or event, a roll vs L with the engine's modifiers, and a Search roll.
- **Missions never use book mode**; they are rolled among the written ones. Aborting moves to step 2, since one written mission leaves nothing else to roll.
- **Forest of #41** — decided when #41 is written, after the MVP; the model already holds side maps.
- **Roadmap rewritten** — the user said the old engine list was a preliminary exploration and asked for the most practical one. A skeleton first (E1–E5: dice, game state, map and time, engine/interface protocol, book mode), then tasks that each write an engine part with its content, then step 2. Renumbered; the YAML batches follow the order the engine needs them.
