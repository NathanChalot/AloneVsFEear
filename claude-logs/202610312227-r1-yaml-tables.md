## Decisions

- **IDs: kind prefix, then roll** (`table.town_exploration.7`, nested `table.random_encounter.3.3-5`); a named entry takes its own ID (`mission.bring_home_the_bacon`). Readable in code and saves, unique by construction. Rejected: roll-based only (opaque `table.mission.3`), bare slugs (collisions across kinds).
- **Files in the package, one per table, ID inside the file.** The engine finds them wherever installed; parallel batches do not share files; files can move without changing IDs. Rejected: a top-level `content/` folder, one file per kind.
- **A catalogue of every table now**, which batches empty. References validate against it, and it gives book mode its fallback (dice and Markdown source). Rejected: stub files per table, an allowlist in tests.
- **The Unique-creatures sentence of Random Encounter is a shared note** pointed to by 3 / 6, 6 / 1-3 and 6 / 4-6, shown with those entries in book mode until the engine rerolls by itself (E10). A table's own `text` (how to roll it, its modifiers) is applied by the engine and shown only on request. Rejected: keeping it only in 6 / 4-6, copying it three times, table text shown on demand only.
- **Table slugs**: a short name from the heading, its singular or plural kept (`table.random_book`, `table.random_objects`); Search rolls is `table.search`.
- **Mission table `text`** is the Mission paragraph of How the Game Works. The engine applies its reroll rule, so it is only read on request. "Below" was dropped (in the Markdown too): words pointing at the page layout go, like page references.
- **`refs`** list only what an entry tells you to roll on or play, not places it merely names ("every time you visit a Clinic box" is a condition the rules check, not an action). Missions never use book mode, so their refs are never shown as actions anyway.
- **Code documentation in `docs/`**, apart from the domain design in `design/`. `content.md` moved there too: it describes a data format (files, fields, IDs, checks), not the game. `docs/architecture.md` describes only what exists and grows at each wrap-up. Splitting `content/model.py` waits until it is needed (R2 to R4 bring their models; the dice codes move in E1). Generated diagrams (pyreverse) left out unless the hand-written page lags.
- **NextSession names the model for each planned session** (family and effort, not version), picked from the model table in `WorkingWithClaude.md`. Fable is not used: it does not follow the same pricing rules. No default effort: each wrap-up reviews the model and effort of the planned sessions with what the session showed. This session ran on Opus at xhigh; nothing in it clearly needed more than high, but no comparison was made.
- **Worktrees**: the user noted a branch would have been enough for a single session. A worktree is now used only for parallel sessions.
