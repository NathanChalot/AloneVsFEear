## Decisions

- **Skill effects are a YAML field** (the user): roll modifiers and parameter changes as data, checked against fixed names; behaviour beyond a number is Python keyed by the Skill's ID. Rejected: a Python table keyed by Skill ID (numbers in code, against D1).
- **Effects are derived, not stored** (the user): read from what the character holds; stored effects with a lifetime of their own come with E8. Rejected: effect records written on the character.
- **A roll made by hand asks only what matters** (the user, after a step-by-step walkthrough of both options): a yes or no per Skill whose bonus depends on the roll's tags. Rejected: picking from every tag of the roll type each time.
- **Bow and Martial Arts are bonuses** (the user, after a walkthrough): +1 / +2 on bow or unarmed Attacks, the weapon keeping its own malus; same totals as the book. Rejected: the Skill changing the weapon's malus.
- **Names** (the user): `effect_targets.py` (rolls and parameters are the two things an effect changes), and `Parameter` for the numbers the rules read (the user found "Value" too generic). The user asked what the module holds: names only, the numbers are calculated.
- **Rulings** (the user, switchable where marked): an Expert amount replaces the Basic one (Agile Expert is +2, not +3); Agile and Dodge give the higher Defense bonus, the other shown set aside (the user asked for it to be visible); Will covers every Will roll and saves vs Fear, Magic, Hypnotism or Psionics; Will (Expert) covers Hypnotism too, read as a slip.
- **Consistency reviews** (the user): fixed review sessions V1 after E9, V2 after E14, V3 after E17, V4 after E20 (merged with the design review that was under Later); findings only about what exists, triaged one at a time, small fixes in the session. The user added a drift check at each wrap-up, limited to what the session touched; anything else goes to "For the next review" in NextSession. Written in WorkingWithClaude, CLAUDE.md and the Readme.
- **Commit split** (the user agreed four): the manual roll could not stay green with a new `roll_vs` without asking the roll type, so commits 3 and 4 were cut by feature (parameters and max, then rolls) instead of engine then interface.
