  Design choices (recommendations first)

  1. Where Skill effects are written
     - A (recommended): an effects field on each Skill in the YAML, built from a
       small fixed vocabulary that the loader checks. Python keeps only
       behaviour (reactions, actions) keyed by Skill ID. This follows D1 ("a
       number the engine reads is a field next to the text"), and items,
       Injuries and Scars can reuse the same field later.
     - B: a Python table keyed by Skill ID. It's simpler today, but it puts the
       numbers in code against D1.
  2. Effects in the state
     - Derived (recommended): effects aren't stored. The engine collects them on
       demand from what the character holds (Skills now; items in E9, Injuries
       in E13). Removing the source removes its effects for free, and the state
       still holds only IDs.
     - Effects that have no held source ("+1 for 3 boxes" from an event) become
       stored records with a lifetime in E8.
  3. The manual roll in book mode: the player picks the roll type (Attack,
     Defense, Save…).
     - Recommended: the engine then asks a yes/no question only for the tags its
       held modifiers depend on, e.g. "A save vs poison, infection or disease?"
       if the character has Resilient. The typed modifier stays for what the
       engine can't track yet: weapon modifiers until E12, and notes.
     - The alternative is that the player picks tags from a full list every
       time.
  4. Bow and Martial Arts: both are roll modifiers on tagged Attacks.
     - Bow gives +1 / +2 to bow Attacks; Martial Arts gives +1 / +2 to unarmed
       Attacks.
     - The weapon's own malus (-1 for an unskilled bow, -2 unarmed) comes with
       E12, or is typed by the player until then.
     - The arithmetic matches the book in every case, and these two Skills don't
       need a "skilled" switch.

⏺ Here's the same book-mode moment under each option, step by step. The example
  character, Ana, has Resilient (+1 to saves vs poison, infection or disease)
  and Agile (+1 Defense, +1 to saves to climb, jump or avoid danger). She enters
  a box, and the engine reaches an entry it can't read yet. The entry says:
  "Toxic fumes: save vs L4 or lose 2 Life."

  Manual roll, option 1: ask only what matters

  1. The engine reaches the unreadable entry. The screen shows its text and the
     book-mode menu: Apply the text, then where does it lead? [t] table [e] 
     event [g] gain [l] lose [v] roll vs L … [d] done.
  2. Ana types v.
  3. The engine asks which roll. The screen lists [1] Attack [2] Defense [3] 
     Save [4] Escape …. Ana types 3.
  4. The engine asks the level. The screen shows L? , and Ana types 4.
  5. The engine looks through Ana's Skills for Save modifiers and finds two.
     Each one depends on what the save is about, so it asks once per Skill:
     - Is it a save vs poison, infection or disease? (Resilient +1) [y/n]: Ana
       types y.
     - Is it a save to climb, jump or avoid danger? (Agile +1) [y/n]: Ana types
       n.
  6. The engine asks for anything it can't know. The screen shows her notes,
     then Other modifier (Enter for none): . Ana presses Enter.
  7. The engine rolls a 3, adds Resilient's +1 for a total of 4, which makes L4.
     The screen shows Save vs L4: rolled 3, Resilient +1, total 4. Success.
  8. The book-mode menu comes back. She succeeded, so she loses nothing and
     types d.

  A character with no Skills that touch saves gets no question at step 5. For a
  Defense roll, Agile applies whatever the roll is about, so it's added without 
  asking.

  Manual roll, option 2: pick from all tags

  Steps 1–4 are the same. At step 5 the screen lists every tag a save can have:
  [1] poison [2] infection [3] disease [4] fear [5] magic [6] hypnotism [7] 
  psionics [8] climb [9] jump [10] avoid danger [d] done.
  Ana types 1, then d. The engine then finds that Resilient matches. Every
  player sees this list on every save, whatever Skills they have.

  My recommendation is option 1: it asks fewer questions, and they're about the
  Skills the player actually has. Book mode is temporary anyway: once an entry
  is written (E10 onwards), the engine makes the roll itself, with its tags, and
  asks nothing.

  ---

  Bow, in the same style

  Ana has the Bow Skill (Basic) and shoots at a creature with her bow. Until
  E12, fights are applied by hand.

  Option "bonus":
  1. Ana types v, then picks Attack, then the creature's L.
  2. The screen asks Is it an Attack with a bow? (Bow +1) [y/n]. Ana types y.
  3. The screen asks Other modifier:. Ana types -1: the bow's own malus, which
     every archer has, as written on the bow.
  4. The screen shows Attack vs L3: rolled 4, Bow +1, -1, total 4. The +1 and -1
     cancel, and the total is what the book says (a skilled archer attacks
     "without modifier").
  5. From E12, the engine knows the bow gives -1 and nobody types anything:
     rolled 4, bow -1, Bow +1, total 4.

  Option "rule on the malus":
  1. Same as above.
  2. Same question.
  3. Ana must know that her Skill removes the bow's -1, so she types 0 (or +1 at
     Expert). The book's rule is applied in her head.
  4. The screen shows Attack vs L3: rolled 4, total 4.
  5. From E12, the bow's code checks "does the character have Bow?" and skips
     its own -1.

  Both give the same totals in every case. The bonus option keeps Bow a plain
  bonus like Fighter's, with nothing to remember, and the screen shows where
  each number comes from. Martial Arts works the same way, with unarmed at -2
  and the Skill at +1 or +2.

  Plan

  Vocabulary — a new vocabulary.py, shared by the content and the engine like
  dice.py:
  - the roll types: Attack, Defense, Save, Escape, Stealth, Charisma, Strength,
    Magic, Will, Search;
  - only the tags the Skills need for now;
  - the values effects can change: max Life, max Sanity, carry limit, Food
    interval, surprise chance, Clue cost.

  A bow Attack is also a ranged one: the combat chapter lists bows among the
  ranged weapons. So a "yes" to Bow's question skips Good Shot's.

  YAML: each Skill gets an effects list, made of three kinds of entry:
  - {roll, tags, basic, expert, group}: a roll modifier. Tags are "any of
    these"; modifiers in the same group don't stack, and the highest applies.
  - {value, basic, expert}: added to a value. Investigator's "minimum 1" and
    Danger Sense's "no chance" become floors on the value.
  - Dodge's balance, Faith and Medic: nothing in the YAML. Their behaviour is
    Python, written in their task (E12, E18, E11/E13), and E7 adds a pending
    test for each.

  Engine (engine/effects.py plus Game):
  - Effects are collected from the Skills held. max() is calculated.
  - adjusted(value, base) serves the parameters that later tasks read: surprise
    chance, Clue cost, Food interval, carry limit.
  - Gaining a Skill raises the current value by however much the max rose: at
    creation, when buying, and when upgrading to Expert (+1 for Tough).
  - roll_vs(level, roll, tags, modifier) and search() collect their modifiers.
    The result lists the modifiers applied and the ones set aside.

  Book mode and terminal: the manual roll follows the walkthrough you chose. For
  the yes/no question, Choose gets an optional about field: what the question
  is about (the Skill and its tags), so the interface can phrase it. The roll
  display lists each modifier by name.

  Not in E7:
  - The Food upkeep keeps every 5 boxes. E8 plugs in the interval, together with
    its open question on changing it mid-game, and Eating Disorder.
  - The carry limit is used from E9, surprise from E12, Clue costs when a text
    first charges Clues.

  Commits, each tested:
  1. Rulings and design (rulings.md, rolls.md, book_errors.md).
  2. Vocabulary, loader and the Skills' YAML.
  3. Effects in the engine: max, values, rolls, Search.
  4. The manual roll and the terminal.
