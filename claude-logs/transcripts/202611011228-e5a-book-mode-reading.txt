  E5a goal

  When the character arrives in a box, the engine rolls the right table and
  shows the entry it lands on. A new box rolls Town Exploration; a visited box
  (Home included) has a 1 in 6 chance of a Random Encounter. The player can then
  follow the entry to another table, and every entry reached is recorded. Once
  every box of a sheet has been visited, the player can attach a new sheet. Done
  when: you can walk the town in the terminal with every box's entry shown, and
  walk onto a new sheet once the first is full.

  Proposed design

  Shape: a new module engine/book.py, called by the loop after each move. It
  holds what to do on arriving, and following an entry to another table.
  - Game.roll_table(id) rolls the dice and goes down into nested tables, so
    Random Encounter rolls a d6 and then another d6. It records what was reached
    and returns the dice results and the entry. A catalogued table (one not
    copied to YAML yet) also gets rolled, but it has no entry, only its source
    file and the number rolled.
  - Arrival gets a new flag (first time in this box).
  - New events: Rolled(table_id, results, entry_id | None) and Wandering(face, 
    encounter) for the 1 in 6 roll. The interface looks up the text by ID in
    game.content, so events stay plain data.
  - Following an entry: Choose(FOLLOW, (*entry.refs, OTHER_TABLE, DONE)).
    OTHER_TABLE then asks Choose(TABLE, every table). This covers catalogued
    tables: their text is in Markdown, so their refs are unknown and the player
    needs a way to say "Undead table". The loop repeats until the player picks
    DONE.
  - Recording: each entry reached counts as PLAYED, at every level that exists
    (campaign and character; mission once there is one). A place table rolled in
    a box goes into box.places. The list of which tables are places lives in
    Python.

  Three choices change what I build. My recommendation comes first in each:

  1. How a table's own rules text is shown. The task says to decide this now.
     - (a) Recommended: the interface decides. The terminal shows the text the
       first time it rolls that table in a game, and again when you type r at
       the follow prompt. The engine is not involved.
     - (b) An engine option "read the rules" inside the follow request.
     - (c) Only the first time, tracked in the game state.
  2. Attaching a sheet.
     - (a) Recommended: a new turn action, "attach a sheet". It is offered only
       when some free spot touches a full sheet. You choose where it goes, then
       walk onto it with normal moves. This uses the existing Game.add_sheet as
       it is.
     - (b) Moves also offer the boxes across the edge of a full sheet, and
       stepping onto one attaches its sheet. This is smoother to play but the
       map drawing gets harder.
  3. Events ("play event #12") wait for R6. There are no event IDs yet, and the
     plan has the events batch (R6) choose them. Until then the player reads the
     event in the Markdown, so E5a offers no event option. OK?

  Known gaps, left for E5b:
  - Town Exploration 7 ("Roll d6. On 1-5 House, on 6 Special Events"): E5a
    offers both tables and you pick one after rolling the d6 yourself. E5b's
    manual roll will do it properly.
  - Safe Houses and left-behind encounters skipping the 1 in 6: nothing can be
    marked or left behind yet, so they come with E5b, E11 and E15.

  Do you agree with 1a, 2a and 3? Once you answer, I'll write the scenario tests
  first.

⏺ The book never says whether Home is a Safe House, so the Home question is a
  rule interpretation. Here it is first, then your four questions.

  Is Home a Safe House?

  The design pages (design/safe-houses.md, design/glossary.md) say "Home is not
  a Safe House", but cite no source. What the rules text says:

  - Visited boxes: "Every time you move through a box that you already visited…
    Roll a 1 in 6 chance of a Random Encounter instead"
    (5_how_the_game_works.md). The starting box gets no exception.
  - Bring Home the Bacon: "you may leave any of your items in your starting box
    (or in any Safe House)". This names the starting box apart from Safe Houses,
    so Home is probably not one.
  - Safe Houses are made only by table results (House, Clinic, Street…) and heal
    you on every visit. Nothing makes Home heal you.

  The options:

  - (a) Recommended: Home is not a Safe House. It rolls the 1 in 6 like any
    visited box. This follows the letter of the rules. I'd write it in
    design/rulings.md as an interpretation, since today it is an unsourced line
    in the design.
  - (b) Home is a Safe House: no encounter there, maybe healing too. This is a
    kinder reading, but the book never says it.
  - (c) A middle way: no random encounter at Home, but no healing either. This
    is invented.

  It can be kept switchable. Which do you want?

  1. The table's rules text, from the player's side

  A table carries two kinds of text: each entry, and the table's own rules. For
  Town Exploration, the own rules are "Roll on this table every time you move
  into an unexplored area… You may Search ONLY after dealing with…". The
  question is when you see the own rules.

  (a) Shown the first time, then on request (recommended)
  Box 7.
  Town Exploration table: 3 + 5 = 8
    Rules: Roll on this table every time you move into an unexplored area… 
  (first time only)
    8: Roll on the Store table or the Street table, your choice.
  1) Store table  2) Street table  3) Another table  4) Done   (r: the table's 
  rules)
  The next Town Exploration roll shows only the entry. Typing r shows the rules
  again.

  (b) Only on request, as a numbered option
  Town Exploration table: 3 + 5 = 8
    8: Roll on the Store table or the Street table, your choice.
  1) Store table  2) Street table  3) Another table  4) Read the table's rules  
  5) Done
  You never see the rules unless you ask for them.

  (c) Only the first time, ever

  This looks like (a) without r. The game remembers which tables you have
  already seen, even after a save and resume, and you can never read the rules
  again.

  In (a), only the terminal handles this. Another interface, such as a GUI,
  could make its own choice without any change to the engine. In (b), the engine
  itself offers the option to every interface.

  2. Switching later from 2a to 2b

  Yes, it's cheap. The engine already has add_sheet. For 2b:
  - moves would also offer the boxes just across the edge of a full sheet;
  - stepping onto one of those boxes would call add_sheet first;
  - the terminal would draw those boxes.

  A few scenario tests would change their scripted answers. Nothing else depends
  on how the choice is made.

  3. Events

  I don't recommend moving R6 earlier. It's a big, messy batch (42 events,
  damaged text), and E5a doesn't need the event texts. You read catalogued
  tables in the Markdown, and events would work the same way. What would be
  missing is mainly the recording. The rulings say each event is played once per
  campaign, and some tables give a fallback "if you have already played #1". So
  the game needs to know which events were played.

  - (a) Recommended: a small event catalogue in E5a, like catalogue.yaml for
    tables. It holds only the 42 numbers with IDs event.1 to event.42 and their
    source file, so no text is copied. You get a new option "a numbered event":
    you pick its number, the game points you to the Markdown and records the
    event as played. R6 later fills in the text without changing the IDs. Since
    the book numbers its events, event.12 is the natural ID and is unlikely to
    change.
  - (b) No events until R6. You read events in the Markdown and nothing is
    recorded.

  Why "book.py"?

  It's named after book mode: the fallback for any content the engine can't play
  yet. Its job is: roll a table, tell the interface which entry was reached,
  record it, and offer to follow that entry to another table or event. In E5a
  nearly everything goes through it. From E10 on, written entries play
  themselves and only unwritten ones still come here. So it stays in the code
  for good and shrinks in use as content gets written.

  Arriving (new box: Town Exploration; visited box: 1 in 6) is a different job.
  It's the start of the arrival flow that E11 completes. I'd put it in loop.py
  for now. Arriving then hands what it rolls to book mode. I'm open to a
  different name than book.py, fallback.py for example.
