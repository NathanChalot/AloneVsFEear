⏺ Answering in order.

  1. "Boxes do not reset". Yes, that's the creator's answer: the box number
  carries on across missions of the same campaign. I extended it to a new
  character too. After a death, the new character joins the same campaign, so
  the counter stays where it was. My Food rule follows from that: you eat
  whenever the campaign's box number is a multiple of 5, whoever is playing.

  Say the old character dies at box 37 and the new one starts at 38. Their first
  meal is box 40, 3 boxes later instead of 5. The creator's answer is about
  missions, not deaths, so applying it to a new character is my extension. The
  alternative is to count 5 boxes from the new character's own first box. That's
  your call, so I can write it up as a ruling if you want it.

  2. Latest or an earlier sheet. My code already allows either. The new sheet
  can attach to any full sheet it shares a side with. It doesn't have to be the
  latest one.

  3. "Distance around a missing sheet". This is the open item in town-map.md.
  Distance is currently max(column gap, row gap) on the grid. If sheets form an
  L, the straight line between two boxes can cross a spot with no sheet, so the
  real walk is longer than that count. For example, with a sheet on the left and
  one below, the corner sheet is missing. Two boxes on opposite arms are "2
  apart" by the grid count, but you'd have to walk around the gap. I kept the
  simple grid count. It only matters for choosing the closest Safe House.

  4. Position after death. Yes, you're right. It belongs to the character-death
  task (E13), and I only flagged it. Right now the position stays where the old
  character died.

  Starting a sheet after a mission. I can't tell if you mean the same thing as
  the design's open item, so here is what it says. After a mission, the creator
  allows a new sheet even if the current one isn't full. What is open is where
  the character goes: do they walk onto it from an edge, or start anywhere on
  it?

  Reaching a border on one side without filling the sheet is something else, and
  the design doesn't mention it. The rules say a sheet's open edges are walls
  until the sheet is full. That means a character at the border of an unfilled
  sheet can't continue in that direction. This is my reading of the book: you
  stay in the sheet until you've visited all 30 boxes (or finished a mission).
  Is that what you were asking about?

  MoveKind. My wording was unclear. The design lists several kinds of move, and
  each one chooses the destination box differently:
  - Normal: any neighbour. Implemented.
  - Escape: a visited neighbour, or any neighbour if none is visited.
    Implemented.
  - Led astray (Whispering Presence): a visited box, otherwise a random
    neighbour. Not implemented.
  - Forced (#42): you're pushed into a neighbour. Not implemented.
  - Jump (#16): a box 1 or 2 away. Not implemented. Its details are still open
    in the design: does the box in between count, and does the jump take 1 or 2
    boxes of time?

  Each one only changes which boxes you may choose, so the same move method can
  handle them later. I'd add them when I write the events that use them.

  Do you want me to write the Food-clock choice (and the "attach to any full
  sheet" choice) into design/rulings.md as switchable, then run the wrap-up?
