⏺ Short answer: a note on the table itself only helps if book mode shows it.
  Most table-level text never needs to be shown, because it's the engine's job.

  What you'd see in book mode

  Say you walk into a visited box and the 1 in 6 comes up:

  Box 14 (visited): random encounter!
  Random Encounter: d6 = 3, d6 = 6
    Roll on the Unique Vampires table.

    [1] Go to the Unique Vampires table   [2] Manual actions…

  You pick 1. The engine rolls Unique Vampires, which isn't copied yet, so you
  get "Unique Vampires table, entry 4: see 5_30_unique_vampires_table.md". If
  you killed that vampire two missions ago, the book says to reroll. Between E5
  and E10 the engine doesn't do that reroll yet, so you have to do it by hand,
  and you only know to if the sentence was on screen with row 3 / 6. From E10
  on, the engine does the reroll itself ("vampire 4 already killed, rerolled:
  2"), and the sentence becomes reference text only.

  Two kinds of table-level text

  - How to roll the table. Town Exploration's "roll every time you move into an
    unexplored area", Search's "+1 with Investigator", the Mission table's
    "reroll if same as last time". The engine applies these, so showing them on
    every roll would be noise. I'd make this text available on demand (a "this
    table's rules" action) and never print it automatically.
  - Rules about some results. The Unique sentence is one: it applies to three
    rows. Book mode has to show it with those rows, or nobody will apply it
    before E10.

  So "once, on the table" only works if book mode shows the table text, and
  showing it everywhere is noisy. A middle way: write the sentence once in the
  table as a named note, and have the three Unique rows point to it. Book mode
  then shows the row text plus its note.
