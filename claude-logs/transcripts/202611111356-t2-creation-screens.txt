  4. The taken Skill

  Strikethrough is an ANSI code (ESC[9m). iTerm2 and most Linux terminals show
  it, but I'm not sure macOS Terminal.app does. Where it isn't supported, it
  shows as plain text or stray characters. It would also be the first styling in
  a game that has none yet, and it would end up as escape codes in tests and
  logs. My recommendation is plain text now: 8) Good Shot (taken). "(taken)"
  after the name keeps the names lined up. Bold, dim or strikethrough would come
  later as one decision for the whole terminal, and I'd add that to the
  after-MVP list. Your line had "(taken)" both before and after the name: which
  did you mean?

  5A. Showing the park sentence after the content fix

  The YAML would keep the parts separate. The heading's text is "-1 to Attack
  rolls." and the stick's extra is the park sentence. The loader already gives
  each variant both: weapon.text is the full text (the heading's text plus the
  extra) and weapon.extra is the sentence alone. So each screen picks what it
  needs:
  - The full text on the character sheet or the inventory: "Stick: -1 to Attack
    rolls. You may pick up a stick every time you visit a park."
  - Only the extra at the knife-or-stick question, because the shared part is
    already in the line above.

  The hammer already works this way.
